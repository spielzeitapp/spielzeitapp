# Public tournament audience app — TEST prototype

Independent Vite entry at /turnier-app/ with its own scoped Web App Manifest, trophy icons and minimal service worker. No AuthProvider, SessionProvider, role switcher or account registration. Public data uses the existing sanitized tournament API; no database schema/data changes. Existing public tournament and admin display flows are untouched.

Spectators select a participant or all teams, choose a personal app accent, and use Start / Spielplan / Live / Tabellen / Mein Team. Team selection and accent are versioned and saved separately per tournament; malformed preference data is ignored. Official colors are only available for the host/current team from the existing DTO, so other team colors are user selectable, not claimed as verified club colors. Score overlays respect home/away perspective and prevent duplicate local/official fixtures. Other teams only show publicly available scores and standings; their private rosters or missing goal events are never fabricated. Details remain in the audience app.

Polling every 5 seconds skips hidden documents and overlapping requests, preserves loaded data on failure, and disposes timers on unmount. Own-team live timing uses the existing live clock component. Choosing another tournament cannot commit an older pending response.

Installation: static manifest start_url and id /turnier-app/, standalone launch restores last visited tournament from device storage. iOS Safari instructions, Android install prompt when available, otherwise browser-menu guidance. Manual browser confirmation required. Dedicated worker does not cache authenticated APIs and does not subscribe to push. Push reminders are explicitly not available in this prototype. Icon installation and actual iOS/Android behavior require device testing; no physical device verification claimed.

Validation: npm run typecheck, npm run build, git diff --check and scripts/tournament-audience-app-test.mjs. Renderer tests cover selection, device persistence scoped per tournament, five-tab navigation, table highlight, in-app event dialog, failed-poll content retention, correct away score overlays, install instructions and honest unavailable-push message. Manifest scope/icon identity and independent entry checked. Build retains pre-existing large chunk warning. Deployed version and entry/manifest/icon/worker routes checked after TEST release.

Palette update: neutral black/white is the default; selectable two-color club presets (including blue/white and red/black) and two custom color inputs are stored per tournament. Legacy single-color preferences remain readable. Day/night preference is saved separately on the device. Secondary color appears on fixture borders and team strip. Start includes a visible Kein Spiel verpassen entry to installation/reminder information; it explicitly states push is not yet active and never requests an unusable browser permission. Renderer checks verify neutral day/night behavior, saved primary/secondary pair and reminder entry.
